Usage Tracking & AI Telemetry

The one place every tracking query lives

Where you are

You have now spent real AI credits in Module 05. This module is where you learn to see them. It opens with the telemetry map and the core queries, then works up to account-wide attribution and waste detection.

This is also the reference module for SQL. Every usage and attribution query in the workshop lives here, so other modules link back rather than reprinting them. The two exceptions are cache KPIs, which belong to Module 07, and budget DDL, which belongs to Module 08.

Learning Objectives

  • Explain why Snowflake splits AI telemetry across separate views instead of one table
  • Produce a single number for total AI spend across CoCo, CoWork, and Agents
  • Attribute AI credits by function, model, user, role, and query tag
  • Detect the eight shadow waste patterns before they reach the invoice
  • Report true cost per use case for a Cortex Agent, including AI function and warehouse spend
Bookmark These Queries

Everything in this module runs in Snowsight. These queries are your real-time FinOps console for AI spend. Save them as worksheets for quick access.

Read this before you blame your SQL: ACCOUNT_USAGE lags ~45 minutes

Most ACCOUNT_USAGE views are refreshed on a delay of roughly 45 minutes, and some run longer. An empty result here usually means the data has not landed yet, not that your query is wrong. This is why the agenda puts a 15 minute break between Module 05 and this module.

Two ways to work around the delay while the slower views catch up:

  • CORTEX_AI_FUNCTIONS_USAGE_HISTORY typically lands in 2 to 5 minutes, so it will show the AISQL spend from Module 05 first. Start there.
  • The INFORMATION_SCHEMA table functions at the end of this module read live metadata with no lag at all.

If a query returns nothing, widen the date range before you change anything else. The queries in this module are written against several days of history precisely so they still return rows on a fresh account.

Cloud Services Credits ≠ AI Token Credits

query_history.credits_used_cloud_services measures cloud services overhead (query compilation, metadata) - not AI token credits. A Cortex call costing 0.5 AI credits may show only 0.000036 in cloud services.

The real AI cost lives in dedicated views: CORTEX_AI_FUNCTIONS_USAGE_HISTORY (CREDITS column) and CORTEX_AISQL_USAGE_HISTORY (TOKEN_CREDITS column). Queries 2 to 6 below use these dedicated views.

A

The AI Telemetry Map

The first surprise for most people is that there is no single "AI spend" table. Snowflake splits AI telemetry by product surface and execution layer, which is why CoCo, CoWork, and Cortex Agents each get their own history view. Once you understand that split, the seven views stop looking arbitrary.

User actions versus background pipelines

CoCo and CoWork record what actual people did: a developer writing SQL in a worksheet, a analyst asking a question in chat. Cortex Agents record what applications did: API calls, custom pipelines, multi-step backend workloads. Snowflake keeps them apart so adoption metrics for a chat product are never blurred with application execution logs.

Why agents need their own lens

Agents bill additively. One user question can trigger a Cortex Search lookup, a generated SQL execution, and an LLM synthesis step, and each sub-call lands as its own row. If that were merged into the user-facing views, a single question would look like several, and your cost-per-question metric would be meaningless.

The seven views

Latency varies by view. Most ACCOUNT_USAGE views land in about 45 minutes, while CORTEX_AI_FUNCTIONS_USAGE_HISTORY is typically 2 to 5 minutes.

View Tracks Key columns Answers the question
CORTEX_AI_FUNCTIONS_USAGE_HISTORY AISQL function calls CREDITS, FUNCTION_NAME, MODEL_NAME, ROLE_NAMES Which function and model is burning credits?
CORTEX_AISQL_USAGE_HISTORY AISQL token metering rollups TOKEN_CREDITS, TOKENS, QUERY_TAG What is my cost per million tokens, and who is it tagged to?
SNOWFLAKE_COCO_USAGE_HISTORY Snowflake CoCo across CLI, Desktop, and Snowsight TOKEN_CREDITS, TOKENS_GRANULAR, INTERFACE, USER_NAME Which developers and interfaces drive assistant spend?
SNOWFLAKE_COWORK_USAGE_HISTORY Snowflake CoWork business assistant TOKEN_CREDITS, TOKENS_GRANULAR, SERVICE_TYPE What does knowledge-work AI adoption cost?
CORTEX_AGENT_USAGE_HISTORY Programmatic Cortex Agent execution AGENT_NAME, AGENT_TAGS, TOKEN_CREDITS, METADATA What does each agent use case cost, and which one is over-calling tools?
CORTEX_SEARCH_DAILY_USAGE_HISTORY Search serving and indexing CREDITS, SERVICE_NAME, CONSUMPTION_TYPE Am I paying standing cost for a service nobody queries?

Two naming traps that will cost you an afternoon

CoWork still reports as Intelligence. The product is Snowflake CoWork, but SERVICE_TYPE and the older SNOWFLAKE_INTELLIGENCE_USAGE_HISTORY view may still say SNOWFLAKE_INTELLIGENCE. Filter for both.

Do not double count CoCo. SNOWFLAKE_COCO_USAGE_HISTORY already covers all interfaces and exposes INTERFACE for slicing. The per-interface views such as CORTEX_CODE_CLI_USAGE_HISTORY are drill-downs, not additions. Summing them together with the unified view inflates your numbers.

B

Total AI Spend in One Number

Before drilling into any single surface, get the total. When a CFO asks what AI costs, this is the query that answers it: developer assistants, business assistants, and programmatic agents, unioned into one result.

Query 1: Absolute total Snowflake AI architecture spend

Executive KPI

When to run: Monthly, and any time someone asks for the headline number.

SQL 
-- Comprehensive AI credit expenditure audit.
-- The timestamp column differs by view, which is the most common cause of
-- a failed UNION here:
--   CoCo org view   -> USAGE_TIME
--   CoWork org view -> START_TIME
--   Agent view      -> START_TIME
SELECT
    'Cortex Code / CoCo Developer Assistant'            AS ai_layer,
    usage_time                                          AS event_time,
    account_name,
    user_name,
    token_credits
FROM SNOWFLAKE.ORGANIZATION_USAGE.SNOWFLAKE_COCO_USAGE_HISTORY

UNION ALL

SELECT
    'Snowflake CoWork Business Assistant'               AS ai_layer,
    start_time                                          AS event_time,
    account_name,
    user_name,
    token_credits
FROM SNOWFLAKE.ORGANIZATION_USAGE.SNOWFLAKE_COWORK_USAGE_HISTORY

UNION ALL

SELECT
    'Programmatic Cortex Agents API / App Layer'        AS ai_layer,
    start_time                                          AS event_time,
    NULL                                                AS account_name,
    user_name,
    token_credits
FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AGENT_USAGE_HISTORY
ORDER BY event_time DESC;

The Agent view is account-scoped. For a true organization-wide rollup, run an org-level Agent variant if your environment exposes one, or union account-level extracts into a central reporting table.

C

Core Tracking Queries

These four are the daily working set. Save them as Snowsight worksheets. Queries 2 through 5 all read the dedicated AI views rather than QUERY_HISTORY, for the reason in the warning above.

Query 2: AI Credits by Cortex Function

Weekly Review

When to run: Weekly FinOps review - uses the dedicated CORTEX_AI_FUNCTIONS_USAGE_HISTORY view for accurate AI token credits (not cloud services overhead).

SQL 
SELECT
    FUNCTION_NAME,
    COUNT(*)                                    AS call_count,
    ROUND(SUM(CREDITS), 4)                      AS total_ai_credits,
    ROUND(AVG(CREDITS), 6)                      AS avg_credits_per_call,
    ROUND(MIN(CREDITS), 6)                      AS min_credits,
    ROUND(MAX(CREDITS), 6)                      AS max_credits,
    ROUND(SUM(CREDITS) * 2, 2)                  AS est_dollars
FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AI_FUNCTIONS_USAGE_HISTORY
WHERE START_TIME >= DATEADD(day, -7, CURRENT_TIMESTAMP)
GROUP BY FUNCTION_NAME
ORDER BY total_ai_credits DESC;

Query 3: Model Cost Comparison

Key Insight

When to run: After Exercise 4 in Module 05, to see real AI credit cost per model from CORTEX_AI_FUNCTIONS_USAGE_HISTORY, not estimates.

SQL 
SELECT
    MODEL_NAME,
    FUNCTION_NAME,
    COUNT(*)                                    AS calls,
    ROUND(SUM(CREDITS), 4)                      AS total_ai_credits,
    ROUND(AVG(CREDITS), 6)                      AS credits_per_call,
    ROUND(SUM(CREDITS) * 2, 2)                  AS est_dollars
FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AI_FUNCTIONS_USAGE_HISTORY
WHERE START_TIME >= DATEADD(hour, -2, CURRENT_TIMESTAMP)
  AND FUNCTION_NAME IN ('COMPLETE', 'AI_COMPLETE')
GROUP BY MODEL_NAME, FUNCTION_NAME
ORDER BY total_ai_credits DESC;

Query 4: Hourly AI Spend Trend

Pattern Analysis

When to run: To identify usage patterns and anomalies - tracks real AI credits from the dedicated view, not cloud services overhead.

SQL 
SELECT
    DATE_TRUNC('hour', START_TIME)              AS hour_bucket,
    FUNCTION_NAME,
    COUNT(*)                                    AS ai_calls,
    ROUND(SUM(CREDITS), 4)                      AS ai_credits,
    ROUND(SUM(CREDITS) * 2, 2)                  AS est_dollars
FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AI_FUNCTIONS_USAGE_HISTORY
WHERE START_TIME >= DATEADD(day, -1, CURRENT_TIMESTAMP)
GROUP BY 1, 2
ORDER BY 1 DESC, ai_credits DESC;

Query 5: Cost Projection Query

Non-Negotiable

When to run: Before running any AI at scale. Use it after Module 05, Exercise 6.

SQL 
-- Step 1: Find your recent AI call costs from the dedicated view:
SELECT
    QUERY_ID,
    FUNCTION_NAME,
    MODEL_NAME,
    ROUND(CREDITS, 6)                           AS ai_credits,
    START_TIME
FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AI_FUNCTIONS_USAGE_HISTORY
WHERE START_TIME >= DATEADD(hour, -1, CURRENT_TIMESTAMP)
ORDER BY START_TIME DESC
LIMIT 10;
SQL 
-- Step 2: Project costs at scale using real AI credits:
WITH sample_cost AS (
    SELECT
        SUM(CREDITS)                            AS sample_credits,
        COUNT(*)                                AS sample_calls
    FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AI_FUNCTIONS_USAGE_HISTORY
    WHERE QUERY_ID IN (
        -- *** PASTE YOUR TEST QUERY IDs HERE ***
        'your_query_id_1',
        'your_query_id_2'
    )
)
SELECT
    sample_credits,
    sample_calls,
    ROUND(sample_credits / NULLIF(sample_calls, 0), 6) 
                                                AS credits_per_call,
    ROUND(sample_credits * 100, 4)              AS projected_500_rows,
    ROUND(sample_credits * 10000, 2)            AS projected_50k_rows,
    ROUND(sample_credits * 100000, 2)           AS projected_500k_rows,
    -- Dollar estimates at ~$2/AI Credit
    ROUND(sample_credits * 100000 * 2, 2)       AS projected_500k_dollars
FROM sample_cost;
This Query is Non-Negotiable

This projection query must be run before any production AI pipeline. Paste your test query_ids and know your cost before you scale.

D

Shadow Waste Detection

Shadow waste is AI credit consumption that delivers little or no business value. AI services are serverless - no warehouse to watch, no query fails, no alert fires. Credits silently drain. The queries below detect the most common patterns.

8 Shadow Waste Patterns

Idle Search services, over-sized models, redundant calls, verbose prompts, agent loops, dev/test in prod, cost spikes, and missing attribution. The queries below target each pattern.

Query 6: Idle Cortex Search Detection

Shadow Waste #4

When to run: Weekly. Cortex Search services consume credits for serving (6.3 credits/GB/month) even with zero queries. Idle services = 100% waste.

SQL 
WITH costs AS (
    SELECT SERVICE_NAME,
           SUM(CASE WHEN CONSUMPTION_TYPE = 'SERVING'
                    THEN CREDITS ELSE 0 END)           AS serving_credits,
           SUM(CASE WHEN CONSUMPTION_TYPE = 'BATCH'
                    THEN CREDITS ELSE 0 END)           AS query_credits,
           SUM(CASE WHEN CONSUMPTION_TYPE = 'EMBED_TEXT_TOKENS'
                    THEN CREDITS ELSE 0 END)           AS embedding_credits
    FROM   SNOWFLAKE.ACCOUNT_USAGE.CORTEX_SEARCH_DAILY_USAGE_HISTORY
    WHERE  USAGE_DATE >= DATEADD('day', -30, CURRENT_TIMESTAMP())
    GROUP  BY SERVICE_NAME
)
SELECT SERVICE_NAME,
       serving_credits,
       embedding_credits,
       query_credits,
       ROUND(query_credits / NULLIF(serving_credits, 0) * 100, 1) AS query_pct
FROM   costs
WHERE  serving_credits > 0
ORDER  BY query_pct ASC;
Reading the Results

query_pct near 0% means the service is incurring standing serving cost but nobody is querying it. Consider suspending or dropping unused services:

ALTER CORTEX SEARCH SERVICE my_idle_svc SUSPEND SERVING;  -- stops standing cost
ALTER CORTEX SEARCH SERVICE my_idle_svc SUSPEND;          -- stops both serving + indexing
DROP CORTEX SEARCH SERVICE IF EXISTS my_abandoned_svc;    -- permanent removal

CONSUMPTION_TYPE values: SERVING (standing cost, 24/7), EMBED_TEXT_TOKENS (indexing on data change), BATCH (query usage).

Query 7: Over-Sized Model Detection

Shadow Waste #1

When to run: Monthly - developers default to the most capable (expensive) model. Compare credits_per_1M_tokens across models to find where a cheaper model would suffice.

Source: CORTEX_AISQL_USAGE_HISTORY - has TOKENS and TOKEN_CREDITS granularity.

SQL 
SELECT MODEL_NAME, FUNCTION_NAME,
       SUM(TOKENS)        AS total_tokens,
       SUM(TOKEN_CREDITS)  AS total_credits,
       ROUND(SUM(TOKEN_CREDITS)
             / NULLIF(SUM(TOKENS),0) * 1000000, 2)
                            AS credits_per_1m_tokens
FROM   SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AISQL_USAGE_HISTORY
WHERE  USAGE_TIME >= DATEADD('day', -30, CURRENT_TIMESTAMP())
GROUP  BY MODEL_NAME, FUNCTION_NAME
ORDER  BY credits_per_1m_tokens DESC;
Savings Potential: 40 to 75%

Replace AI_COMPLETE('sentiment...') with AI_SENTIMENT(text) for 40 to 70% savings. Replace AI_COMPLETE('classify...') with AI_CLASSIFY(text,[...]) for 50 to 75%. Task-specific functions are purpose-built and cheaper.

Query 8: Redundant / Duplicate AI Calls

Shadow Waste #2

When to run: Weekly - pipelines re-processing unchanged rows every scheduled run, multiple users running overlapping queries. 10K rows hourly = same tokens 24x/day.

Fix: Incremental processing (WHERE ai_processed_at IS NULL), cache AI results, tag pipelines with QUERY_TAG.

SQL 
-- Find repeated calls by user/day
SELECT h.USER_ID, u.NAME,
       h.FUNCTION_NAME,
       DATE_TRUNC('day', h.START_TIME)  AS day,
       COUNT(*)                         AS daily_calls,
       SUM(h.CREDITS)                   AS daily_credits
FROM   SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AI_FUNCTIONS_USAGE_HISTORY h
JOIN   SNOWFLAKE.ACCOUNT_USAGE.USERS u
       ON h.USER_ID = u.USER_ID
WHERE  h.START_TIME >= DATEADD('day', -7, CURRENT_TIMESTAMP())
GROUP  BY h.USER_ID, u.NAME, h.FUNCTION_NAME, day
HAVING COUNT(*) > 20
ORDER  BY daily_credits DESC;

Query 9: Verbose / Bloated Prompts

Shadow Waste #3

When to run: Monthly - prompts with excessive instructions or entire documents when only a paragraph is relevant. 50-word filler x 100K rows = 12.3 credits wasted.

Fix: Trim prompts, pre-filter with LEFT(document_text, 500), use AI_COUNT_TOKENS as pre-flight check.

SQL 
-- Compare avg tokens/call over time
SELECT FUNCTION_NAME,
       DATE_TRUNC('week', USAGE_TIME)  AS week,
       AVG(TOKENS)                     AS avg_tokens_per_call,
       SUM(TOKEN_CREDITS)              AS weekly_credits
FROM   SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AISQL_USAGE_HISTORY
WHERE  USAGE_TIME >= DATEADD('day', -60, CURRENT_TIMESTAMP())
GROUP  BY FUNCTION_NAME, week
ORDER  BY FUNCTION_NAME, week;
Prompt Engineering IS Cost Engineering

Rising avg_tokens_per_call over time = prompt bloat. Check TOKENS_GRANULAR for input vs output split. Truncating input can cut costs 50%+.

Query 10: Uncontrolled Agent Loops

Shadow Waste #5

When to run: Weekly - agents orchestrate multi-step tool calls. Without budgets, an agent can loop endlessly. Worst case: 100K+ tokens = 0.18+ credits per question.

Signal: MAX(TOKEN_CREDITS) >> AVG(TOKEN_CREDITS) = unbounded calls. Set token + time budgets on all agents.

SQL 
-- Find runaway agent calls
SELECT DATE_TRUNC('day', USAGE_TIME) AS day,
       MAX(TOKEN_CREDITS)            AS max_call,
       AVG(TOKEN_CREDITS)            AS avg_call,
       COUNT(*)                      AS total_calls
FROM   SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AISQL_USAGE_HISTORY
WHERE  USAGE_TIME >= DATEADD('day', -14, CURRENT_TIMESTAMP())
GROUP  BY day
ORDER  BY day DESC;

Query 11: Dev/Test in Production

Shadow Waste #6

When to run: Monthly - developers experimenting with AI using production credentials. Notebooks, ad-hoc queries, prototypes consuming prod credits without business value.

Fix: RBAC (REVOKE USE AI FUNCTIONS from dev roles), separate dev/prod accounts, enforce tagging.

SQL 
-- AI usage by role (LATERAL FLATTEN on ROLE_NAMES array)
SELECT r.VALUE::STRING   AS role_name,
       h.FUNCTION_NAME,
       COUNT(*)           AS calls,
       SUM(h.CREDITS)     AS total_credits
FROM   SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AI_FUNCTIONS_USAGE_HISTORY h,
       LATERAL FLATTEN(input => h.ROLE_NAMES) r
WHERE  h.START_TIME >= DATEADD('day', -30, CURRENT_TIMESTAMP())
GROUP  BY role_name, h.FUNCTION_NAME
ORDER  BY total_credits DESC;

Query 12: Week-over-Week Cost Anomaly Detection

Shadow Waste #7

When to run: Weekly - a code change or misconfigured schedule causes a spike. Unnoticed until the monthly bill. Example: WHERE clause change - 1K rows becomes 1M.

Fix: Activate tag-based AI feature budgets (Module 08) with email notifications; enable low-latency refresh (1hr vs 6.5hr default). Tag users so cost-center attribution works.

SQL 
-- Week-over-week anomaly detection
WITH daily AS (
    SELECT USAGE_DATE::DATE AS day,
           SUM(CREDITS_BILLED) AS credits
    FROM   SNOWFLAKE.ACCOUNT_USAGE.METERING_DAILY_HISTORY
    WHERE  SERVICE_TYPE IN ('AI_SERVICES','CORTEX_AGENTS','CORTEX_CODE_CLI','CORTEX_CODE_SNOWSIGHT','SNOWFLAKE_INTELLIGENCE')
      AND  USAGE_DATE >= DATEADD('day', -60, CURRENT_DATE())
    GROUP  BY day
)
SELECT day, credits,
       LAG(credits, 7) OVER (ORDER BY day)   AS last_week,
       ROUND((credits - LAG(credits, 7) OVER (ORDER BY day))
             / NULLIF(LAG(credits, 7) OVER (ORDER BY day), 0)
             * 100, 1)                         AS wow_pct
FROM   daily
ORDER  BY day DESC;
Reading the Results

wow_pct > 200 = spend more than tripled vs same day last week - investigate immediately. Even +50% week-over-week warrants review. Pair this with budget email alerts for proactive detection.

Query 13: Missing Cost Attribution

Shadow Waste #8

When to run: Monthly - without tagging, AI costs = one aggregated number. Nobody knows which team/project/pipeline owns the spend. Can't charge back, can't optimize.

Fix: Enforce ALTER SESSION SET QUERY_TAG='team=X,project=Y,env=prod'. Target: >90% credits should be tagged.

SQL 
-- Check tagging coverage
SELECT CASE WHEN QUERY_TAG IS NOT NULL AND QUERY_TAG != ''
            THEN 'Tagged' ELSE 'Untagged'
       END                              AS attribution,
       COUNT(*)                          AS calls,
       SUM(TOKEN_CREDITS)                AS credits,
       ROUND(SUM(TOKEN_CREDITS)
             / (SELECT SUM(TOKEN_CREDITS)
                FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AISQL_USAGE_HISTORY
                WHERE USAGE_TIME >= DATEADD('day', -30, CURRENT_TIMESTAMP()))
             * 100, 1)                   AS pct_of_total
FROM   SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AISQL_USAGE_HISTORY
WHERE  USAGE_TIME >= DATEADD('day', -30, CURRENT_TIMESTAMP())
GROUP  BY attribution;
Unattributed Spend Cannot Be Optimized

Query tagging is free - one SQL line per session. Use a consistent standard like team=<team>,project=<project>,env=<env> to enable automated cost reporting and chargeback.

E

Cost Per Use Case

Everything so far answers "what did AI cost". The question a business owner actually asks is narrower: what did my use case cost. For Cortex Agents that question is easier to answer than most people expect, because the agent is already a named object and Snowflake records its name on every row.

You do not need tags to get started

CORTEX_AGENT_USAGE_HISTORY carries AGENT_NAME, AGENT_DATABASE_NAME, and AGENT_SCHEMA_NAME as ordinary columns. If one agent corresponds to one use case, grouping by the agent name gives you cost per use case with no setup at all.

Reach for tags when the mapping is not one to one: a use case served by several agents, or a cost-center rollup that does not match how your agents happen to be named.

Token credits are not the whole bill

This is the part most cost-per-use-case reports get wrong. An agent request can spend credits in three separate places, and TOKEN_CREDITS only covers the first:

  • TOKEN_CREDITS - the orchestration and LLM tokens for the request itself.
  • METADATA:ai_functions_credits - any AI functions the agent invoked along the way.
  • METADATA:sql_query_credits - warehouse compute for SQL the agent ran, for example a Cortex Analyst tool call generating and executing a query.

An analytics agent that leans on Cortex Analyst can spend more on warehouse compute than on tokens. Report only TOKEN_CREDITS and you will understate that use case and misprice the chargeback.

Query 14: True cost per agent, all three components

Chargeback

When to run: Monthly, and whenever a team asks what their agent costs. This is the headline cost-per-use-case query.

SQL 
-- Cost per agent (use case), including AI function and warehouse spend
SELECT
    AGENT_DATABASE_NAME || '.' || AGENT_SCHEMA_NAME || '.' || AGENT_NAME  AS use_case,
    COUNT(DISTINCT REQUEST_ID)                                           AS requests,
    ROUND(SUM(TOKEN_CREDITS), 3)                                         AS token_credits,
    ROUND(SUM(COALESCE(METADATA:ai_functions_credits::FLOAT, 0)), 3)     AS ai_function_credits,
    ROUND(SUM(COALESCE(METADATA:sql_query_credits::FLOAT, 0)), 3)        AS warehouse_credits,
    ROUND(SUM(TOKEN_CREDITS
            + COALESCE(METADATA:ai_functions_credits::FLOAT, 0)
            + COALESCE(METADATA:sql_query_credits::FLOAT, 0)), 3)        AS total_credits,
    ROUND(SUM(TOKEN_CREDITS
            + COALESCE(METADATA:ai_functions_credits::FLOAT, 0)
            + COALESCE(METADATA:sql_query_credits::FLOAT, 0))
          / NULLIF(COUNT(DISTINCT REQUEST_ID), 0), 4)                    AS credits_per_request
FROM   SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AGENT_USAGE_HISTORY
WHERE  START_TIME >= DATEADD('day', -30, CURRENT_TIMESTAMP())
GROUP  BY use_case
ORDER  BY total_credits DESC;
Read credits_per_request before you read the total

A large total can simply mean a popular agent. The number that tells you whether a use case is efficient is the per-request figure, and it is the one to trend week over week. A rising per-request cost on flat usage means the agent is doing more work per question than it used to.

Query 15: Roll up to a cost center with AGENT_TAGS

Attribution

When to run: Monthly, once you have more agents than you can track by name. Apply the tag first with the DDL in Module 08.

AGENT_TAGS is an array of Snowflake object tags, not the QUERY_TAG you set on a session. Each entry carries a level, so a tag inherited from the agent's database appears alongside one set directly on the agent. Prefer the most specific level when both exist.

SQL 
-- Agent spend rolled up by the cost_center object tag
WITH agent_cost AS (
    SELECT REQUEST_ID,
           AGENT_TAGS,
           TOKEN_CREDITS
             + COALESCE(METADATA:ai_functions_credits::FLOAT, 0)
             + COALESCE(METADATA:sql_query_credits::FLOAT, 0)  AS total_credits
    FROM   SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AGENT_USAGE_HISTORY
    WHERE  START_TIME >= DATEADD('day', -30, CURRENT_TIMESTAMP())
),
labelled AS (
    SELECT c.REQUEST_ID,
           c.total_credits,
           -- a tag set on the agent itself wins over one inherited from the database
           COALESCE(
             MAX(CASE WHEN UPPER(t.value:tag_name::STRING)  = 'COST_CENTER'
                       AND UPPER(t.value:level::STRING)     = 'CORTEX_AGENT'
                      THEN t.value:tag_value::STRING END),
             MAX(CASE WHEN UPPER(t.value:tag_name::STRING)  = 'COST_CENTER'
                      THEN t.value:tag_value::STRING END)
           )                                                   AS cost_center
    FROM   agent_cost c,
           LATERAL FLATTEN(input => c.AGENT_TAGS, OUTER => TRUE) t
    GROUP  BY c.REQUEST_ID, c.total_credits
)
SELECT COALESCE(cost_center, '(untagged)')  AS cost_center,
       COUNT(*)                             AS requests,
       ROUND(SUM(total_credits), 3)         AS total_credits
FROM   labelled
GROUP  BY cost_center
ORDER  BY total_credits DESC;
Three things that will make these numbers look wrong
  • The warehouse figure arrives late. sql_query_credits comes from a separate cost-attribution pipeline and can lag the rest of the row by up to 8 hours. It is NULL until then, so a report run too early shows token cost only. It also excludes queries run on Adaptive Warehouses.
  • CoWork traffic is not in this view. Requests originating from Snowflake CoWork are recorded in SNOWFLAKE_COWORK_USAGE_HISTORY instead, even when an agent did the work. Add that view if your use case is user-facing.
  • Tag edits take time to propagate. Changing a tag can take up to 8 hours to be reflected where budgets consume it, so do not re-run and panic five minutes after tagging.
Which tagging mechanism applies where

These are three different systems and they do not substitute for each other. QUERY_TAG is set per session and shows up on AISQL usage, which is what Query 13 measures. AGENT_TAGS and USER_TAGS are object tags applied to an agent or a user, and they are what the agent and budget views read.

In practice you want the same taxonomy in all three, for example a single cost_center tag, so one vocabulary covers AISQL, agents, and the budgets in Module 08.
