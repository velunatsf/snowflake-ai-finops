Function Reference Card

Keep this section open while you work through the exercises. It gives the signature, cost basis, and best-use note for every function you are about to run. The full rate tables and model cards live in Module 02, Section D.

AI_SENTIMENT(text [, categories])

Returns an OBJECT with sentiment categories (positive, negative, neutral, mixed, unknown)

Lowest Cost
Best For

Customer feedback, support tickets, reviews, social media

Cost

0.095 credits per 1M characters

Notes

No model selection - Snowflake-optimized. Optional categories array for aspect-level sentiment.

FinOps Tip

AI_SENTIMENT is the most cost-efficient Cortex function for sentiment analysis. Always use it instead of prompting AI_COMPLETE() for sentiment.

AI_COMPLETE(model, prompt)

General-purpose LLM generation with model selection

Variable Cost
Best For

Classification, extraction, generation, complex reasoning

Cost

Varies widely by model (see Module 02, Section E)

Notes

First parameter is model name as string

Cost Warning

Most expensive function category. Always specify the cheapest model that meets your quality requirements. The cost difference between mistral-7b and claude-4-sonnet can be 50x or more.

AI_SUMMARIZE_AGG(expr)

Aggregate function - summarizes a column of text data across multiple rows

Moderate Cost
Best For

Summarizing columns of reviews, call transcripts, logs, meeting notes

Cost

Uses underlying model rates (typically llama-based)

Notes

Handles datasets larger than max context window. For single-row summarization, use AI_COMPLETE with a summarize prompt.

AI_TRANSLATE(text, source_lang, target_lang)

Translates text between supported languages with auto-detect

Moderate Cost
Best For

Multilingual content, localization, international data

Cost

0.333 credits per 1M characters

Languages

Zero-shot classification into provided categories (single or multi-label)

Exercise 1

Sentiment Analysis

Lowest Cost AI_SENTIMENT()

Context: Analyze customer feedback sentiment using Snowflake's most cost-efficient AI function.

Approach A: New AI_SENTIMENT (returns OBJECT with category strings)

SQL 
SELECT
    customer_id,
    customer_name,
    LEFT(feedback_text, 80)                     AS feedback_preview,
    AI_SENTIMENT(feedback_text)                 AS sentiment_result,
    AI_SENTIMENT(
        feedback_text
    ):categories[0]:sentiment::VARCHAR          AS sentiment_label
FROM cortex_lab.ai_workshop.customer_feedback
LIMIT 20;

Approach B: Legacy SENTIMENT (returns numeric score -1 to 1)

SQL 
SELECT
    customer_id,
    customer_name,
    LEFT(feedback_text, 80)                     AS feedback_preview,
    SNOWFLAKE.CORTEX.SENTIMENT(
        feedback_text
    )                                           AS sentiment_score,
    CASE
        WHEN SNOWFLAKE.CORTEX.SENTIMENT(feedback_text) > 0.3
             THEN 'Positive'
        WHEN SNOWFLAKE.CORTEX.SENTIMENT(feedback_text) < -0.3
             THEN 'Negative'
        ELSE 'Neutral'
    END                                         AS sentiment_label
FROM cortex_lab.ai_workshop.customer_feedback
LIMIT 20;
AI_SENTIMENT vs SENTIMENT

AI_SENTIMENT() (new) returns an OBJECT: {"categories":[{"name":"overall","sentiment":"positive"}]}. Extract via :categories[0]:sentiment::VARCHAR.

SNOWFLAKE.CORTEX.SENTIMENT() (legacy) returns a float from -1.0 to 1.0. Both are highly cost-efficient - no model parameter required.

Exercise 2

Text Classification

Lower Cost AI_CLASSIFY()

Context: Route customer feedback to support teams by categorizing into predefined topics.

SQL 
SELECT
    customer_id,
    market_segment,
    LEFT(feedback_text, 80)                     AS feedback_preview,
    AI_CLASSIFY(
        feedback_text,
        ['billing',
         'technical_issue',
         'general_inquiry',
         'complaint',
         'praise']
    ):labels[0]::VARCHAR                        AS category
FROM cortex_lab.ai_workshop.customer_feedback
LIMIT 20;
AI_CLASSIFY vs AI_COMPLETE

AI_CLASSIFY() is significantly cheaper than using AI_COMPLETE() with a classification prompt. Always use the specialized function when available.

Exercise 3

Text Extraction

Medium Cost mistral-7b

Context: Extract structured information from unstructured text using a budget-tier model.

SQL 
SELECT
    customer_id,
    feedback_text,
    AI_COMPLETE(
        'mistral-7b',
        CONCAT(
            'Extract the main complaint topic from this customer ',
            'feedback in 3 words or less. ',
            'Reply with only the topic, nothing else. ',
            'Feedback: ', feedback_text
        )
    )                                           AS extracted_topic
FROM cortex_lab.ai_workshop.customer_feedback
WHERE LENGTH(feedback_text) > 50
LIMIT 10;
Model Choice Matters

Notice we use mistral-7b - the budget tier model. For a simple 3-word extraction task, a premium model would cost 10 to 20x more with no quality gain.

ROI

What Right-Sizing Should Save You

Before you run the model comparison, here is the result you are trying to reproduce. The most common form of wasted AI spend is reaching for AI_COMPLETE() when a dedicated function already does the job, or pinning a premium model to a task a budget model handles fine.

Instead of Use Expected Savings Why
AI_COMPLETE('Classify sentiment...') AI_SENTIMENT(text) 40 to 70% Purpose-built model, no prompt tokens, lower per-call cost
AI_COMPLETE('Classify into: A, B, C...') AI_CLASSIFY(text, [...]) 50 to 75% Zero-shot classification without prompt engineering overhead
AI_COMPLETE('Translate to French...') AI_TRANSLATE(text, 'fr') 40 to 60% Optimized translation model, 90+ languages, no prompt tokens
AI_COMPLETE('Summarize this...') on a premium model AI_COMPLETE() on mistral-7b 30 to 60% A budget model is usually sufficient for summarization
AI_COMPLETE() on claude-4-sonnet AI_COMPLETE() on mistral-7b 10x to 50x Right-sizing: the cheapest model that still meets your quality bar

Treat these as expectations to validate, not guarantees. Your prompt shape and data will move the numbers. Exercises 4 and 5 measure the real figure for your own workload, and Module 06 has the query that finds these patterns automatically across an entire account.

Exercise 7

Boolean Filtering with AI_FILTER

Lower Cost AI_FILTER()

Context: Filter rows using natural language conditions instead of writing complex LIKE/REGEXP patterns. AI_FILTER returns TRUE/FALSE for each row based on a text description.

SQL 
-- AI_FILTER: Find orders with urgent/escalation language
SELECT
    O_ORDERKEY,
    O_ORDERPRIORITY,
    O_COMMENT,
    SNOWFLAKE.CORTEX.AI_FILTER(CONCAT(
        O_COMMENT,
        'This text mentions a delay, complaint, or urgent issue'))
FROM cortex_lab.ai_workshop.ORDERS
LIMIT 10;
AI_FILTER Syntax

AI_FILTER takes a single argument: the text concatenated with a natural language description of the boolean condition. Use it as a cheaper alternative to AI_COMPLETE() for yes/no filtering tasks.

Common Pitfalls
  • Can use AI_FILTER directly (no prefix needed) or SNOWFLAKE.CORTEX.AI_FILTER (fully qualified)
  • The argument is CONCAT(column, 'description') - not two separate arguments
  • Returns a boolean, so use directly in WHERE or SELECT

Use in WHERE clause

SQL 
-- Filter only rows where the condition is TRUE
SELECT
    O_ORDERKEY,
    O_ORDERPRIORITY,
    O_COMMENT
FROM cortex_lab.ai_workshop.ORDERS
WHERE SNOWFLAKE.CORTEX.AI_FILTER(CONCAT(
    O_COMMENT,
    'This text mentions a delay, complaint, or urgent issue'))
LIMIT 10;

Key Takeaways

  1. AI_SENTIMENT() is the cheapest function in the catalog. Use it for sentiment instead of prompting AI_COMPLETE()
  2. AI_CLASSIFY() beats AI_COMPLETE() on cost for classification, and AI_FILTER() beats it for boolean filtering
  3. Model choice can mean a 10x to 50x cost difference on the identical task
  4. Always test small, measure the real cost, then project before scaling
  5. The right model is the cheapest one that clears your quality bar, and routing can pick it for you

Break time (15 min), and there is a reason for it

The spend you just generated does not appear in Snowflake's billing views instantly. Most ACCOUNT_USAGE views lag by roughly 45 minutes. If you jump straight into Module 06 and query them, you will get empty results and conclude something is broken when it is not.

Take the break now. It closes most of the gap for the queries you ran at the start of this module. When you return, Module 06 opens with the views that refresh fastest, so you will have data to work with even if the slower views are still catching up.

One thing worth doing before you step away: leave your worksheet open. Coming back to a live session avoids re-running the AI calls, which would cost credits a second time.
