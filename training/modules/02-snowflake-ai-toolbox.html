The single most useful habit on this page

Reach for the specialized function before you reach for AI_COMPLETE(). B

Agents, CoWork, and the Shift Away From Analyst

Beyond AISQL functions, Snowflake’s AI surface has shifted toward agents and personal work orchestration. FinOps must budget these domains separately from warehouse compute.

Transition from Cortex Analyst → Cortex Agents

Snowflake recommends transitioning from standalone Cortex Analyst to Cortex Agents. Agents support Analyst capabilities with higher answer quality and expanded natural-language analytics.

  • Streamlined SQL generation (Apr 2026): Agents that use Analyst semantic views as tools now generate SQL directly, instead of calling Cortex Analyst as a separate step. Lower latency and better accuracy.
  • Response / tool blocks: cortex_analyst_text_to_sql is replaced by system_execute_sql. The tool-use block includes generated sql; the result includes query_id, result_set, and final sql.
  • Config: Agent definitions and semantic views usually need no change. Apps or monitors that parse tool-type strings must update.
  • Observability: In CORTEX_AGENT_USAGE_HISTORY, granular tokens/credits no longer split out cortex_analyst - usage is reported under cortex_agents.

FinOps note: Agent costs are additive (orchestration + tools + warehouse for executed SQL). Meter CORTEX_AGENTS SERVICE_TYPE and agent usage history - do not assume Analyst API metering covers Agent SQL.

Snowflake CoWork Formerly Intelligence

AI personal work agent and central orchestrator across sub-agents. Connects to business tools (Slack, Jira), learns preferences, generates PPT/PDF deliverables, and is available on iOS.

FinOps note: Product name is CoWork; budget domain / SERVICE_TYPE often remains SNOWFLAKE_INTELLIGENCE. Include in AI feature budgets (Module 08).

Snowflake CoCo Formerly Cortex Code

AI coding agent for development. Official product name is Snowflake CoCo (Snowflake’s documented rename of Cortex Code). Handles complex workflows from Desktop, CLI, Snowsight, Slack, or mobile via a single prompt - each step consumes tokens.

FinOps note: Separate SERVICE_TYPEs for CLI vs Snowsight; use per-user CoCo credit limits + tag-based AI feature budgets.

Prefer Agents over standalone Analyst

For new NL-to-SQL and analytics workloads, build on Cortex Agents (and CoWork when you need cross-tool orchestration). Keep the standalone Analyst API only for hard legacy dependencies. Budgets and dashboards must include Agents + CoWork + CoCo, not only AISQL functions.

C

Snowflake CoCo Formerly Cortex Code

Snowflake CoCo is Snowflake's AI coding agent - available in Snowsight, Desktop, CLI, Slack, and mobile. It adds capabilities beyond the SQL functions covered above and participates in Dynamic Model Routing via Cortex AI Gateway when enabled.

What CoCo Adds

  • Natural language → SQL and multi-file coding workflows
  • Code explanation and documentation
  • Agentic multi-step reasoning from a single prompt
  • CLI / Desktop / Snowsight / Slack surfaces
  • Integration with MCP servers and external tools

Cost Tracking for CoCo

  • CORTEX_CODE_SNOWSIGHT_USAGE_HISTORY
  • CORTEX_CODE_CLI_USAGE_HISTORY
  • Tracks user, timestamp, tokens, credits
  • TOKENS_GRANULAR / credits breakdown by model
Key Insight

CoCo is the AI layer that helps you write the SQL that calls other Cortex functions - and it burns tokens on every step. You install the CLI in Module 04, cap it with AI feature budgets in Module 08, and use it to generate the Streamlit dashboard in Module 09.

D

What Each Tool Costs

Module 01 showed the token to credit to dollar chain with a single example rate. This section is the reference material behind it. Every rate table for the whole workshop lives here, so later modules point back to this section instead of repeating the numbers.

The first thing to internalize is that Snowflake does not bill every AI feature the same way. There are four distinct billing shapes.

Billing shape Applies to What that means for you
Per token, model dependent AI_COMPLETE(), AI_CLASSIFY(), AI_SUMMARIZE_AGG(), AI_EMBED() Model choice is the dominant cost lever. Same prompt, different model, up to 50x the bill.
Per character, fixed model AI_SENTIMENT(), AI_TRANSLATE() No model to choose and no prompt overhead. Almost always cheaper than prompting an LLM to do the same job.
Warehouse compute FORECAST(), ANOMALY_DETECTION(), CLASSIFICATION(), CONTRIBUTION_EXPLORER() Billed as Platform Credits, not AI Credits. Normal warehouse sizing and auto-suspend rules apply.
Standing cost Cortex Search services Accrues continuously while the service is resumed, even at zero queries. The only AI cost here that you pay for doing nothing.

Cortex Search: the one AI cost that runs while you sleep

Every other cost in this table is pay-per-call. Cortex Search is different. It has two components, and the first one accrues whether or not anyone queries it.

Cost Component Rate Trigger
Serving compute 6.3 credits/GB/month Continuous while the service is resumed, even with zero queries
Indexing (warehouse + AI_EMBED tokens) Variable On source data change: warehouse refresh plus embedding token cost

An idle Search service with serving resumed is 100 percent waste on the serving line. Audit weekly: is each service actually being queried? Module 06 has the detection query that finds idle services from CORTEX_SEARCH_DAILY_USAGE_HISTORY. The fix is here:

SQL 
-- Suspend serving only (stops the 6.3 credits/GB/month standing cost)
ALTER CORTEX SEARCH SERVICE my_search_svc SUSPEND SERVING;

-- Suspend indexing only (stops warehouse + embedding costs on data changes)
ALTER CORTEX SEARCH SERVICE my_search_svc SUSPEND INDEXING;

-- Suspend both
ALTER CORTEX SEARCH SERVICE my_search_svc SUSPEND;

-- Resume when needed (typically takes a few minutes)
ALTER CORTEX SEARCH SERVICE my_search_svc RESUME;

-- Permanently remove an abandoned service
DROP CORTEX SEARCH SERVICE IF EXISTS my_abandoned_svc;
Agent and CoWork costs stack on top

The rates above price a single function call. Cortex Agents and CoWork add orchestration tokens plus the cost of every tool they invoke, so one user question can bill several times. That additive model is why Agents get their own telemetry view, which you will query in Module 06, and their own budget domain in Module 08.

Context Window = Capacity, Not Cost

The context window (e.g. 32K tokens) is the maximum a model can process per call - you only pay for tokens actually used. If your prompt is 500 tokens and the response is 200 tokens, you pay for 700 tokens, not 32K. Prefer Dynamic Model Routing (Section F) for Agents, CoWork, and CoCo when it is available.

F

Dynamic Model Routing

Dynamic Model Routing (Cortex AI Gateway; private preview) automatically selects the most affordable model that can complete each step of agent work. It is wired into CoCo, CoWork, and third-party agents that use the gateway.

How routing works

  • Advisor pattern: a smaller model tries first; escalates to a larger model as a tool if needed.
  • Classifier: routes straightforward / repetitive work to cheaper models based on task patterns.
  • Governance: only admin-approved models; respects data residency; routing decisions are logged.
  • Optional: you can still pin a single model or a restricted set - auto is not required.

FinOps impact

  • No separate fee for the routing decision - you pay tokens for the model that ran.
  • Snowflake cites up to ~3x token efficiency vs frontier-only paths on some internal workloads.
  • For high-volume AI_COMPLETE SQL jobs, still pick Budget or Standard models deliberately (Section D).
  • For Agents / CoWork / CoCo, prefer auto within an approved pool when available.

AISQL: explicit model vs Dynamic Model Routing

DMR is wired into CoCo, CoWork, and Agents via Cortex AI Gateway. For AISQL, AI_COMPLETE('auto', ...) is available in private preview when your account has Dynamic Model Routing enabled. If unavailable, pin Budget or Standard models deliberately.

SQL 
-- Explicit model pin
SELECT AI_COMPLETE('llama3.1-70b', 'Summarize in one sentence: ' || feedback_text)
FROM cortex_lab.ai_workshop.customer_feedback LIMIT 3;

-- Dynamic Model Routing (private preview when enabled)
SELECT AI_COMPLETE('auto', 'Summarize in one sentence: ' || feedback_text)
FROM cortex_lab.ai_workshop.customer_feedback LIMIT 3;
Related: AI mode for sensitive data classification (Public Preview)

Classification profiles can enable ai_mode: true to use openai-gpt-5-mini for additional semantic categories beyond standard scanning. This is a governance feature (Trust Center / data privacy), not an AISQL lab - but it does consume AI capacity. Enable only where semantic enrichment justifies the cost; VARIANT/OBJECT/ARRAY columns and tables with >300 columns are not AI-enriched.

Knowledge Check

Q1: Which Cortex function is most cost-efficient for analyzing customer feedback sentiment?

AI_SENTIMENT() - It uses Snowflake's optimized internal model at 0.095 credits per 1M characters. Using AI_COMPLETE() with a prompt like "Rate the sentiment of this text" would cost significantly more.

Q2: When should you use AI_CLASSIFY() instead of AI_COMPLETE()?

Use AI_CLASSIFY() when you need to categorize text into a set of predefined categories. It's more cost-efficient and purpose-built for this task. Only use AI_COMPLETE() for classification when you need reasoning, explanations, or categories that emerge dynamically from the text.

Q3: What's the cost difference between mistral-7b and claude-4-sonnet for the same workload?

Approximately 10-50x difference. mistral-7b processes ~8.3M input tokens per credit, while claude-4-sonnet processes ~667K input tokens per credit (input) and only ~133K output tokens per credit. For output-heavy workloads, the difference can be even greater.

Q4: Why prefer Cortex Agents over standalone Cortex Analyst for new analytics apps?

Agents include Analyst capabilities with better NL quality, generate SQL directly via system_execute_sql (lower latency), and are the recommended path. Meter under cortex_agents - not a separate Analyst service step.

Q5: What FinOps benefit does Dynamic Model Routing provide?

Cortex AI Gateway auto-selects the cheapest capable model per step (advisor + classifier), within admin-approved models. No routing fee - you only pay tokens for the model that ran. Prefer auto for Agents/CoWork/CoCo; still pick Budget models deliberately for high-volume AISQL.
