AI Feature Budgets & Spend Controls

Tag-based AI feature budgets, SERVICE_TYPE billing, CoCo guardrails, and model access control

Learning Objectives

  • Create tag-based custom budgets for AI Functions, Agents, CoWork, and CoCo
  • Detect SERVICE_TYPE entries that track AI spend in METERING_DAILY_HISTORY
  • Set CoCo per-user credit limits and understand allowlist vs model RBAC
  • Apply layered governance: AI Feature Budgets → CoCo Limits → Model Access → Usage History
  • Use AI_COUNT_TOKENS to estimate cost before execution and TRY_COMPLETE for production safety
A

New SERVICE_TYPE Billing New Feature

Breaking Change for Cost Dashboards

Four services are getting their own billing types as part of the AI Credits transition. If your cost dashboards only look for AI_SERVICES, you will silently miss spend from these new service types.

Moving to Own SERVICE_TYPE

  • CORTEX_AGENTS
  • CORTEX_CODE_CLI
  • CORTEX_CODE_SNOWSIGHT
  • SNOWFLAKE_INTELLIGENCE (Snowflake CoWork)

Still Under AI_SERVICES

  • AI Functions (COMPLETE, SENTIMENT, etc.)
  • Cortex Analyst (standalone API)
  • Fine Tuning
  • Search Serving / Batch Search
  • Provisioned Throughput

Query: Detect New AI Credit Service Types

Transition Check

When to run: Immediately - check if your account already shows the new service types in METERING_DAILY_HISTORY.

SQL 
SELECT
    SERVICE_TYPE,
    MIN(USAGE_DATE)          AS first_seen,
    MAX(USAGE_DATE)          AS last_seen,
    SUM(CREDITS_BILLED)      AS total_credits_billed,
    SUM(CREDITS_USED)         AS total_credits_used
FROM SNOWFLAKE.ACCOUNT_USAGE.METERING_DAILY_HISTORY
WHERE SERVICE_TYPE IN (
    'AI_SERVICES',
    'CORTEX_AGENTS',
    'CORTEX_CODE_CLI',
    'CORTEX_CODE_SNOWSIGHT',
    'SNOWFLAKE_INTELLIGENCE'
)
GROUP BY SERVICE_TYPE
ORDER BY total_credits_billed DESC;
Action Required for Your Dashboards

If you built cost dashboards that filter on SERVICE_TYPE = 'AI_SERVICES', update them now to also include the four new service types. Otherwise, your AI spend totals will be silently wrong - showing lower costs than actual.

B

Custom AI Feature Budgets GA

Enterprise AI budgeting

Custom budgets can track and enforce spending for AI Functions, Cortex Agents, Snowflake CoWork, and Snowflake CoCo down to team or cost-center level. AI features are shared resources - usage is attributed by tagged users who call them. Docs: Using budgets for AI features.

Prerequisites: Tag Your Users

Before creating the budget, tag users (or automate tags via SCIM) so Snowflake can attribute spend to a business unit.

SQL 
-- Create a cost_center tag (once per account/schema as needed)
CREATE TAG IF NOT EXISTS cost_center;

-- Attribute users to cost centers
ALTER USER ds_jane SET TAG cost_center = 'DataScience';
ALTER USER fin_john SET TAG cost_center = 'FinanceTeam';
-- For this workshop, tag your own training user:
-- ALTER USER USER_COCO SET TAG cost_center = 'DataScience';

Snowsight UI path

  1. Admin → Cost management → Budgets → + Budget
  2. Choose database/schema for budget metadata, set monthly credit limit, optional low latency refresh, alert threshold + emails
  3. On Budget scope: under Tags on users, select cost_center: DataScience (required for AI shared resources)
  4. Under Select resources to monitor, enable: AI Functions, CoCo, Cortex Agents, Snowflake CoWork
  5. Save and review

Programmatic setup (SQL lab)

Lab: Create a cost-center AI feature budget

Hands-On
SQL 
-- 1) Create budget instance
CREATE OR REPLACE SNOWFLAKE.CORE.BUDGET my_ai_budget();

CALL my_ai_budget!SET_LIMIT(5000);
CALL my_ai_budget!SET_EMAIL_NOTIFICATIONS('finops-alerts@yourcompany.com');

-- 2) Scope by user tags (UNION = user matches any listed tag)
-- Prefer SET_USER_TAGS with a TAG reference (current docs pattern):
CALL my_ai_budget!SET_USER_TAGS(
  [
    [(SELECT SYSTEM$REFERENCE('TAG', 'cost_center', 'SESSION', 'APPLYBUDGET')),
     'DataScience']
  ],
  'UNION'
);

-- 3) Add shared AI domains
CALL my_ai_budget!ADD_SHARED_RESOURCE('AI FUNCTION');
CALL my_ai_budget!ADD_SHARED_RESOURCE('CORTEX CODE');
CALL my_ai_budget!ADD_SHARED_RESOURCE('CORTEX AGENT');
CALL my_ai_budget!ADD_SHARED_RESOURCE('SNOWFLAKE INTELLIGENCE');  -- CoWork

-- Optional: verify scope
-- CALL my_ai_budget!GET_BUDGET_SCOPE();
-- SELECT SYSTEM$SHOW_BUDGET_SHARED_RESOURCE_CANDIDATES();
Domain name vs product name

Budget domain SNOWFLAKE INTELLIGENCE tracks Snowflake CoWork. CORTEX CODE tracks Snowflake CoCo (CLI + Snowsight + Desktop). Use product names in conversation; use domain strings in SQL.

Budgets vs hard blocks

AI feature budgets notify (and can run custom actions) at thresholds. For hard per-user stops on CoCo, also set the credit-limit parameters below. For broader AI domains, evaluate per-user quotas (public preview) with block enforcement.

C

Spend Cap - CoCo Credit Guardrails New Feature

Layered with AI feature budgets

AI feature budgets govern team/cost-center spend across AI domains. CoCo per-user credit limits hard-block individual developers on CLI/Snowsight within a rolling 24h window.

How do you govern LLM spend from Snowflake CoCo on a per-user basis? Four tools, each for a different scenario:

Layer Tool Behavior Scope
Proactive Per-user CoCo credit limits Hard block - rolling 24h window Account-wide default + per-user override
Threshold AI feature Budgets Alert / custom action by cost center Tagged users + AI domains
Preventive Model access (RBAC; allowlist legacy) Block expensive models at the source Role / account
Audit Usage History views Attribution after-the-fact by user + model Per surface (CLI / Snowsight)

Per-User Credit Limits Proactive - Blocks Before Spend Happens

Parameter Controls
CORTEX_CODE_CLI_DAILY_EST_CREDIT_LIMIT_PER_USER Snowflake CoCo CLI usage
CORTEX_CODE_SNOWSIGHT_DAILY_EST_CREDIT_LIMIT_PER_USER Snowflake CoCo in Snowsight usage

Set Account-Wide Default + Per-User Override

Guardrail SQL
SQL 
-- Account-wide default: 20 credits/day per user (CLI)
ALTER ACCOUNT SET CORTEX_CODE_CLI_DAILY_EST_CREDIT_LIMIT_PER_USER = 20;

-- Tighter limit for a specific user
ALTER USER USER_COCO SET CORTEX_CODE_CLI_DAILY_EST_CREDIT_LIMIT_PER_USER = 5;

-- Same for Snowsight
ALTER ACCOUNT SET CORTEX_CODE_SNOWSIGHT_DAILY_EST_CREDIT_LIMIT_PER_USER = 20;
ALTER USER USER_COCO SET CORTEX_CODE_SNOWSIGHT_DAILY_EST_CREDIT_LIMIT_PER_USER = 5;

Rolling 24h Window

The limit is a rolling 24-hour window, not a calendar day. If a user hits the cap at 9am Tuesday, they're blocked until 9am Wednesday.

Independent Surfaces

CLI and Snowsight are tracked independently with separate parameters. Cap someone on CLI while leaving Snowsight open, or vice versa.

Two-Level Control

Set an account-wide default, then override per user. Power users get more headroom; restricted roles get tighter limits.

Monthly AI Feature Budgets See Section B

Use tag-based AI feature budgets (Section B) to track AI Functions, Agents, CoWork, and CoCo by cost center. Pair with CoCo per-user limits for hard stops on developer surfaces.

Budgets Alert - They Don't Hard-Block Alone

Budgets are an early warning / custom-action system. Per-user CoCo credit limits (and per-user quotas where enabled) provide hard stops.

Model Access Control Preventive

CORTEX_MODELS_ALLOWLIST is being deprecated

From August 2026 you can only set the allowlist to 'None'; later it is removed. Prefer model RBAC via application roles such as SNOWFLAKE."CORTEX-MODEL-ROLE-LLAMA3.1-70B". Keep allowlist examples below for legacy accounts only.

Restrict which LLM models users can call. Legacy allowlist limits models account-wide; go-forward control is granting model-specific application roles to user roles.

SQL 
-- Preferred: grant model access via RBAC (example)
GRANT APPLICATION ROLE SNOWFLAKE."CORTEX-MODEL-ROLE-MISTRAL-7B"
  TO ROLE cortex_analyst;
GRANT APPLICATION ROLE SNOWFLAKE."CORTEX-MODEL-ROLE-LLAMA3.1-70B"
  TO ROLE cortex_analyst;

-- Legacy allowlist (transitional only)
SHOW PARAMETERS LIKE 'CORTEX_MODELS_ALLOWLIST' IN ACCOUNT;
ALTER ACCOUNT SET CORTEX_MODELS_ALLOWLIST = 'mistral-7b,llama3.1-8b,llama3.1-70b,mistral-large2,snowflake-arctic';
-- Migrate toward:
-- ALTER ACCOUNT SET CORTEX_MODELS_ALLOWLIST = 'None';
Layered Defense

Combine AI feature budgets + CoCo credit limits + model RBAC: budgets govern team spend, limits hard-cap individuals, RBAC prevents expensive model selection.

CoCo Usage History Audit - Attribution After-the-Fact

CORTEX_CODE_CLI_USAGE_HISTORY

Breaks down Snowflake CoCo CLI spend by user and model. One row per usage event. Use this to identify who's spending the most and on which models.

CORTEX_CODE_SNOWSIGHT_USAGE_HISTORY

Same structure for Snowsight-based CoCo usage. CLI and Snowsight tracked in separate views - query both for complete attribution.

Query: Top CoCo Spenders by User & Model

Attribution
SQL 
-- Snowflake CoCo CLI spend by user and model (last 30 days)
SELECT
    h.USER_NAME,
    f.key                       AS model_name,
    SUM(h.TOKEN_CREDITS)        AS total_credits,
    ROUND(SUM(h.TOKEN_CREDITS) * 2, 4) AS est_cost_usd_ai_credits  -- ~$2.00/AI Credit (global)
FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_CODE_CLI_USAGE_HISTORY h,
     LATERAL FLATTEN(input => h.TOKENS_GRANULAR) f
WHERE h.USAGE_TIME >= DATEADD('day', -30, CURRENT_TIMESTAMP())
GROUP BY h.USER_NAME, f.key
ORDER BY total_credits DESC;

-- Repeat with CORTEX_CODE_SNOWSIGHT_USAGE_HISTORY
-- for Snowsight usage attribution

D

Helper Functions for Cost Control

Two helper functions let you estimate cost before execution and handle failures gracefully at scale:

AI_COUNT_TOKENS

Estimate token consumption before running a query. Understand how prompt context impacts cost without spending any AI credits - only compute cost applies.

  • Estimate cost before scaling to full dataset
  • Compare token counts across prompt designs
  • Validate that input fits within model context window
  • Works with AI_COMPLETE, AI_SENTIMENT, AI_CLASSIFY, AI_EMBED, AI_TRANSLATE, AI_SIMILARITY

TRY_COMPLETE

Run AI_COMPLETE but return NULL instead of an error when input exceeds model limits. Prevents query failures when processing variable-length text at scale.

  • Prevents batch query failures on oversized rows
  • Returns NULL for rows that exceed context window
  • Process millions of rows without one bad row killing the job
  • Use with SNOWFLAKE.CORTEX.TRY_COMPLETE()

AI_COUNT_TOKENS - Estimate Before You Spend

Cost Estimation
SQL 
-- Count tokens for an AI_COMPLETE call (no AI credits consumed)
SELECT AI_COUNT_TOKENS('ai_complete', 'mistral-7b',
    'Summarize this feedback: The product arrived late and was damaged.');

-- Compare token counts across models for the same prompt
SELECT
    'mistral-7b' AS model,
    AI_COUNT_TOKENS('ai_complete', 'mistral-7b', prompt) AS tokens
FROM (SELECT 'Summarize: ' || c_comment AS prompt
      FROM SNOWFLAKE_SAMPLE_DATA.TPCH_SF1.CUSTOMER LIMIT 1)
UNION ALL
SELECT
    'llama3.1-70b',
    AI_COUNT_TOKENS('ai_complete', 'llama3.1-70b', prompt)
FROM (SELECT 'Summarize: ' || c_comment AS prompt
      FROM SNOWFLAKE_SAMPLE_DATA.TPCH_SF1.CUSTOMER LIMIT 1);

-- Estimate total tokens before running at scale
SELECT
    COUNT(*) AS total_rows,
    SUM(AI_COUNT_TOKENS('ai_complete', 'mistral-7b',
        CONCAT('Summarize: ', c_comment))) AS total_input_tokens,
    ROUND(total_input_tokens / 8300000, 6) AS est_credits
FROM SNOWFLAKE_SAMPLE_DATA.TPCH_SF1.CUSTOMER;

TRY_COMPLETE - Graceful Failure at Scale

Production Safety
SQL 
-- TRY_COMPLETE returns NULL instead of failing on oversized input
SELECT
    customer_id,
    SNOWFLAKE.CORTEX.TRY_COMPLETE('mistral-7b',
        CONCAT('Summarize: ', feedback_text)
    ) AS summary
FROM cortex_lab.ai_workshop.customer_feedback;

-- Count how many rows would fail (NULL = exceeded context window)
SELECT
    COUNT(*) AS total_rows,
    COUNT(SNOWFLAKE.CORTEX.TRY_COMPLETE('mistral-7b',
        CONCAT('Summarize: ', feedback_text))) AS successful_rows,
    total_rows - successful_rows AS failed_rows
FROM cortex_lab.ai_workshop.customer_feedback;
FinOps Pattern: Estimate, Then Execute

Use AI_COUNT_TOKENS to estimate cost before running at scale, then use TRY_COMPLETE in production to handle edge cases gracefully. This prevents both bill shock and batch failures.
