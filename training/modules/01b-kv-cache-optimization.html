KV Cache Optimization

Prompt cache metrics that drive both cost and performance in multi-turn AI

Learning Objectives

  • Explain why prompt / KV cache can cut repeated-context spend toward ~90%
  • Distinguish cache_read_input, cache_write_input, input, and output
  • Connect high cache-read share to faster multi-turn latency and lower AI Credits
  • Query CoCo and CoWork usage views for weekly cache KPIs
A

Why KV / Prompt Cache Matters

Cost + performance lever (not a daily quota)

In multi-turn CoCo, CoWork, Agents, and REST sessions, most of the prompt is often unchanged history, system instructions, or attached docs. Without caching, every turn re-processes and re-bills that context as fresh input. With prompt (KV) caching, reused context is billed as cache_read_input at a reduced rate. High cache-hit workloads can cut AI spend dramatically (commonly cited toward ~90% on the repeated-context portion). Validate exact rates in the Credit Consumption Table and Snowflake AI pricing.

Cost impact

  • Pay full rate once to write context into cache (cache_write_input)
  • Pay reduced rate to read it on later turns (cache_read_input)
  • Only new tokens each turn bill as standard input
  • FinOps KPI: rising cache-read share with flat/falling total credits

Performance impact

  • Cached KV state avoids re-prefill of the same long context
  • Later turns stay responsive as the thread grows (less redundant compute)
  • Context ring (e.g. 50k / 256k) is session window fill, not a day/month limit
  • Use /compact when the window is full but you need to continue the same thread
Context usage vs spend limits

A UI reading "context usage 20% (~50.1k / 256k Tokens)" measures how full this conversation's model window is. Daily/monthly CoCo limits and AI feature budgets are separate controls (Module 07).

B

Four Token Types to Meter

Snowflake exposes cache telemetry in TOKENS_GRANULAR and CREDITS_GRANULAR on agentic usage views:

  • CORTEX_CODE_CLI_USAGE_HISTORY (and unified SNOWFLAKE_COCO_USAGE_HISTORY)
  • SNOWFLAKE_COWORK_USAGE_HISTORY (org) / account-usage CoWork view
  • CORTEX_AGENT_USAGE_HISTORY for Agents
Metric Meaning FinOps signal
cache_read_input Cached context tokens retrieved and reused on later turns - typically billed at a reduced rate vs standard input High share = healthy reuse; primary savings lever
cache_write_input Initial context tokens processed and written into the cache on the first turn (or when cache is refreshed) Pay once to seed the cache; expect on turn 1
input New, non-cached input tokens processed for the first time this turn Should stay small vs cache reads in long sessions
output Tokens generated by the model in the response Often highest $/token - keep answers concise

Healthy session shape

  1. Turn 1: mostly cache_write_input + some input + output
  2. Turn 2+: growing cache_read_input, small new input, output as needed
  3. Target: cache_read_input >> input for the same conversation

Practices that unlock savings

  • Keep system prompts / large docs stable across turns
  • Continue a session instead of restarting for the same context
  • Avoid rewriting the entire prompt each turn (destroys cache hits)
  • Watch TTL - unused cache entries expire

Weekly Cache KPI Queries

Full lab queries also live in Module 06 Query 13 and training/sql/06-token-tracking.sql.

CoCo CLI + CoWork cache hit rate

FinOps KPI
SQL 
-- CoCo CLI - TOKENS_GRANULAR is OBJECT keyed by model
-- https://docs.snowflake.com/en/sql-reference/account-usage/cortex_code_cli_usage_history
SELECT
    f.key                                               AS model_name,
    SUM(COALESCE(f.value:input::NUMBER, 0))             AS input_tokens,
    SUM(COALESCE(f.value:cache_read_input::NUMBER, 0))  AS cache_read_tokens,
    SUM(COALESCE(f.value:cache_write_input::NUMBER, 0)) AS cache_write_tokens,
    SUM(COALESCE(f.value:output::NUMBER, 0))            AS output_tokens,
    ROUND(
      100.0 * SUM(COALESCE(f.value:cache_read_input::NUMBER, 0))
      / NULLIF(
          SUM(COALESCE(f.value:input::NUMBER, 0)
            + COALESCE(f.value:cache_read_input::NUMBER, 0)
            + COALESCE(f.value:cache_write_input::NUMBER, 0)), 0),
      1)                                                AS cache_read_pct_of_prompt,
    SUM(h.TOKEN_CREDITS)                                AS total_credits
FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_CODE_CLI_USAGE_HISTORY h,
     LATERAL FLATTEN(input => h.TOKENS_GRANULAR) f
WHERE h.USAGE_TIME >= DATEADD('day', -7, CURRENT_TIMESTAMP())
GROUP BY 1
ORDER BY total_credits DESC;

-- CoWork - nested ARRAY (request -> service -> model); org account
-- https://docs.snowflake.com/en/sql-reference/organization-usage/snowflake_cowork_usage_history
SELECT
    svc.key                                               AS service_type,
    mdl.key                                               AS model_name,
    SUM(COALESCE(mdl.value:input::NUMBER, 0))             AS input_tokens,
    SUM(COALESCE(mdl.value:cache_read_input::NUMBER, 0))  AS cache_read_tokens,
    SUM(COALESCE(mdl.value:cache_write_input::NUMBER, 0)) AS cache_write_tokens,
    SUM(COALESCE(mdl.value:output::NUMBER, 0))            AS output_tokens,
    ROUND(
      100.0 * SUM(COALESCE(mdl.value:cache_read_input::NUMBER, 0))
      / NULLIF(
          SUM(COALESCE(mdl.value:input::NUMBER, 0)
            + COALESCE(mdl.value:cache_read_input::NUMBER, 0)
            + COALESCE(mdl.value:cache_write_input::NUMBER, 0)), 0),
      1)                                                  AS cache_read_pct_of_prompt,
    SUM(h.TOKEN_CREDITS)                                  AS total_credits
FROM SNOWFLAKE.ORGANIZATION_USAGE.SNOWFLAKE_COWORK_USAGE_HISTORY h,
     LATERAL FLATTEN(input => h.TOKENS_GRANULAR) tg,
     LATERAL FLATTEN(input => tg.value) req,
     LATERAL FLATTEN(input => req.value) svc,
     LATERAL FLATTEN(input => svc.value) mdl
WHERE h.START_TIME >= DATEADD('day', -7, CURRENT_TIMESTAMP())
  AND svc.key <> 'start_time'
  AND TYPEOF(mdl.value) = 'OBJECT'
GROUP BY 1, 2
ORDER BY total_credits DESC;

Knowledge Check

Q1: What does a high cache_read_input share mean for cost?

Most conversation context is reused from the prompt cache and billed at a reduced rate instead of as full input. That is the primary lever behind large (up to ~90% on repeated-context) savings in multi-turn CoCo / CoWork / Agent sessions.

Q2: Is "context usage 20% (50k / 256k)" a monthly spend limit?

No. It is the current conversation's model context window fill. Spend limits are AI Credits, CoCo daily limits, and tag-based AI feature budgets.

Q3: Name one practice that destroys cache savings.

Restarting a new session for the same large context, or rewriting the full system prompt / docs every turn so prior cache entries cannot hit.
